# CaRePrompt 两天版 Baseline 联调与评估方案

文档时间：2026-07-22 18:01:42 CST  
适用范围：CellAtlas v4 / CaRePrompt AAAI 2027 baseline 实验  
代码目录：`/home/zhaoyh/CellAtlas/benchmarks/v4/baseline/`  
运行产物根目录：`/nfs-medical3/zyh/v4/baseline/`

## 1. 目标

在两天内建立一套可审计、可复现且与 CaRePrompt 同口径的最小 baseline 结果，回答以下问题：

1. CaRePrompt 是否优于固定区域与简单 prompt matching？
2. CaRePrompt 是否优于通用或医学领域的 promptable segmentation model？
3. 多分辨率病理方法是否能够解释 CaRePrompt 的性能，还是 cell-aware region representation 仍提供额外价值？
4. 当前报告的 `Dice = 0.8128` 在同一批 4,000 个 held-out test episodes 上是否具有竞争力？

两天版不重新训练外部 foundation model，也不扩大到 963 WSI。外部方法使用公开冻结权重进行零样本评估；所有接口、阈值、prompt 转换和候选 mask 选择规则先在 validation 上冻结，然后每个 baseline 只读取一次 test。

## 2. 当前证据边界

- 正式主模型仍为冻结的 J5，唯一一次既有 test 结果为 Pixel Dice `0.812773`，摘要中四舍五入为 `0.8128`。
- J3 在同一批 4,000 test episodes 上的 Pixel Dice 为 `0.809926`，是当前唯一严格同口径的内部 test baseline。
- Full-budget J5 和 J10 的现有结果来自 validation，不能与 test `0.8128` 混在同一列中。
- J10/Phase4 的 paired bootstrap 联合门禁未通过；最终主路保留 J5。Phase4 作为完整六模块研究候选和消融项保留，不能在主结果中声称已提升最终 test Dice。
- Phase1 10x DeepLabV3-R50 的 test Dice `0.87161` 是闭集 12 类监督分割且聚合口径不同，只能作为 supervised upper reference；必须重新转换到同一 target-vs-rest episode 协议后才能进入同一主表。

## 3. 两天版方法范围

### 3.1 必做方法

| ID | 方法 | 类型 | 是否需要训练 | 主表角色 |
| --- | --- | --- | --- | --- |
| B0 | J3 partial-Phase5 | 内部 prompt baseline | 否 | 当前同 test 协议基线 |
| B1 | Fixed-SLIC + prompt matching | 内部传统区域 baseline | 否 | 证明 learned region 的必要性 |
| B2 | SAM | 通用 prompt foundation model | 否 | 通用零样本基线 |
| B3 | SAM-Med2D | 医学 prompt foundation model | 否 | 医学域 point/box 基线 |
| B4 | WSI-SAM | 多分辨率病理 prompt model | 否 | 最接近多尺度 WSI 设定的外部基线 |
| Ours | CaRePrompt J5 | 最终冻结模型 | 否 | 主方法，既有 test Dice 0.8128 |

### 3.2 两天内不纳入正式主表

- MedSAM：主要使用 box prompt，与 point/small/large 混合协议不完全一致；时间允许时只做 box-only 补充实验。
- SimpleClick、FocalClick：需要额外统一其迭代点击策略，留给完整版实验。
- PathSegmentor、VISTA-PATH 等文本提示模型：使用类别名称或文本语义，不符合当前 class-agnostic visual prompt 协议。
- 外部方法的 in-domain fine-tuning：两天版不执行，避免不同训练预算造成不可解释的比较。

若任何必做方法缺少公开权重、依赖或明确推理契约，必须保留失败记录并停止该方法，不得静默替换模型、权重或 prompt 类型，也不得添加 fallback。

## 4. 固定数据与评估协议

### 4.1 数据划分

固定使用 200-WSI patient-isolated cohort：

- train：140 WSI；
- validation：30 WSI；
- test：30 WSI。

只读输入：

- cohort manifest：`/nfs-medical3/zyh/v4/phase1/data/cohort200_20260716_010810/cohort_manifest.parquet`；
- tiled GT manifest：`/nfs-medical3/zyh/v4/phase1/data/tiled_gt_cohort200_20260716_011804/tiled_gt_manifest.parquet`；
- 10x tiled patch index：`/nfs-medical3/zyh/v4/phase1/data/tiled_patch_index_cohort200_20260716_013248/patch_index_10x_tiled_gt.parquet`；
- test multiscale token cache：`/nfs-medical3/zyh/v4/phase4/data/multiscale_token_cache_20260722_132500_test`；
- test fine-region labels：`/nfs-medical3/zyh/v4/phase4/data/fine_region_labels_20260722_133300_test`；
- test prompt eligibility：`/nfs-medical3/zyh/v4/phase5/data/prompt_eligibility_20260722_133700_test`。

所有源 WSI、GT、manifest、既有 checkpoint 和 test episode 均为只读，禁止移动、覆盖或修改。

### 4.2 Episode 固定

1. validation 和 test 分别生成不可变的 `episode_manifest.parquet`。
2. 每行至少保存：occurrence ID、dataset index、WSI ID、patient ID、patch 坐标、target class、prompt size、正负 prompt 坐标、源 assignment/region ID 和 GT mask 定位信息。
3. 所有 baseline 使用完全相同的 occurrence 顺序；正式结果固定为 4,000 occurrences。
4. 重复采样 occurrence 不去重，但同时记录唯一 episode index 数量。
5. 禁止因某方法无法处理某个 episode 而静默跳过。失败必须形成显式状态和 coverage 统计。

### 4.3 Prompt 转换

- point：使用冻结 episode 中的正负 region centroid，转换为对应模型的 positive/negative point。
- small/large：优先使用冻结 region assignment 的空间范围生成 box 或 mask prompt；不得从 GT mask 反推提示框。
- 不支持某类 prompt 的模型必须分开报告其可支持子集，不能把 box 结果冒充混合 prompt 总结果。
- SAM 多候选输出只能使用模型 predicted-IoU 或预先冻结的确定性规则选 mask，禁止依据 GT Dice 选择最佳候选。
- 坐标转换必须覆盖 level-0、10x crop、模型 resize 输入和输出回投影四套坐标，并通过可视化审计。

### 4.4 主指标

论文摘要可以只报告 `Dice = 0.8128`，但实验产物必须完整保存：

- pooled Pixel Dice，作为主表 `Dice`；
- per-episode Dice；
- Boundary F1@2px；
- point/small/large 分项；
- 12 类分项；
- prompt conflict 或失败 coverage；
- abstention coverage 与 selective Dice；
- 单 episode 和单 patch 推理时间；
- 峰值 GPU 显存。

主表的所有 Dice 必须来自同一批 4,000 occurrences。不同数据集、不同 prompt 预算或不同聚合定义的公开论文数字不得直接填入主表。

## 6. 两天执行排期

### Day 1 上午：数据契约与统一评估器，预计 4 小时

#### D1.1 静态审计，45 分钟

- 验证 cohort、patch index、GT、eligibility 和 test cache 可读；
- 核对 train/validation/test patient 完全隔离；
- 固定 validation 4,000-occurrence manifest；
- 记录所有外部权重的来源、文件哈希、许可证和输入规范；
- 禁止在此阶段读取 test mask 指标。

验收：行数、split、WSI、patient、坐标、target class 和 prompt 字段全部通过，`failure_lines=0`。

#### D1.2 统一 adapter 与输出协议，2 小时

统一接口：

```python
prediction = adapter.predict(
    image_or_multiscale_inputs,
    positive_prompts,
    negative_prompts,
    prompt_type,
)
```

统一输出：`probability [H,W]`、`binary_mask [H,W]`、`status`、`latency_ms`、`peak_memory_mb` 和模型原始候选信息。

验收：每个 adapter 完成 import、权重 strict load、单次前向和输出范围检查；概率有限且位于 `[0,1]`。

#### D1.3 坐标单测与单例可视化，75 分钟

- 每个方法运行同一个 validation episode；
- 输出 `HE | GT | prompts | prediction | overlay`；
- 检查正负点位置、box 范围、resize 和回投影；
- 检查多分辨率中心对齐；
- 不允许用 GT 修正 prompt 或选择输出。

验收：所有 prompt 均落在预期 region；输出尺寸和 GT 完全一致；无水平/垂直翻转、尺度偏移或 padding 偏移。

### Day 1 下午：64/360 episode smoke，预计 4 小时

#### D1.4 GPU 分配

| GPU | 任务 |
| --- | --- |
| 0–1 | SAM |
| 2–3 | SAM-Med2D |
| 4–5 | WSI-SAM |

Fixed-SLIC、J3 和 J5 使用外部任务完成后的空闲 GPU，或在不争用 NFS/显存时使用 CPU 与单 GPU。

#### D1.5 分级 smoke

每个方法必须依次通过：

1. 1 episode；
2. 64 episodes，覆盖 12 类与 point/small/large；
3. 360 episodes，固定 sampler；
4. 同一命令重复一次，验证 occurrence 顺序和指标确定性。

验收：

- 输入、输出和指标数值有限；
- 64/360 行全部落盘；
- 分片合并后无缺行、重行或跨方法 occurrence 错位；
- 每个 GPU/rank 实际收到样本；
- 日志与配置快照完整；
- 不出现 GT-based candidate selection。

Day 1 结束前冻结每个 baseline 的权重、prompt 转换、阈值、candidate selection、输入 resize 和输出回投影规则。

## 7. 正式运行门禁

任一方法必须全部通过以下门禁：

1. 权重和依赖来源明确，哈希落盘；
2. 输入 shape、dtype、颜色空间、坐标系明确；
3. 单例可视化正确；
4. 64 和 360 episode smoke 完整；
5. 多 GPU 分片无缺失或重复；
6. validation 配置冻结；
7. test 仅运行一次；
8. 不用 GT 选择 mask、阈值或 prompt；
9. 所有失败和 abstention 进入分母或被显式报告；
10. 产物、命令、硬件、耗时和退出码可追溯。

## 8. 停止条件

出现以下任一情况时停止对应方法，不进入 test：

- 权重无法 strict load；
- prompt 坐标或回投影无法通过可视化审计；
- 64/360 smoke 存在缺行、NaN、Inf 或不可解释的空 mask；
- 模型不支持预先声明的 prompt 类型且无法在不改变比较问题的情况下映射；
- 需要使用 GT 选择候选 mask；
- validation 结果只能通过临时阈值扫描或 test 调参获得；
- 外部依赖或权重不可用。

停止后保留日志、失败配置和已完成分片，不删除、不覆盖，也不以其他模型静默替代。

## 9. 两天版完成标准

两天版在以下条件全部满足时视为完成：

- 六个必做方法均有明确状态：`completed` 或有证据的 `failed_gate`；
- 至少 J3、Fixed-SLIC、SAM、SAM-Med2D、WSI-SAM 和 CaRePrompt 使用同一 validation episode manifest；
- 通过门禁的方法完成一次性同协议 test；
- 主表、分项表、效率表、失败表和 paired CI 报告均生成；
- CaRePrompt 的 `Dice = 0.8128` 可与同一 test protocol 下的 baseline 直接比较；
- 不将 Phase1 闭集分割数字或其他论文的异数据集 Dice 混入同一主表；
- 所有 test 配置、权重和结果均有 SHA-256 与 `test_used=true` 元数据；
- 联调状态和最终结论同步更新到本方案或独立时间戳报告。
