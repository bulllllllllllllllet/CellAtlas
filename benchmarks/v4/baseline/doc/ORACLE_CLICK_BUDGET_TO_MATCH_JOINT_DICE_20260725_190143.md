# 达到本文方法单次 WSI Dice 所需的 GT 模拟点击预算

## 1. 问题定义

除最终 WSI Dice 外，新增回答以下问题：**在 GT 引导的逐 patch 提示条件下，SAM 类方法需要多少次模拟用户点击和多少次局部推理，才能首次达到本文方法仅用一次 WSI 种子提示得到的 Dice？**

该指标用于量化局部交互方法为了匹配本文方法单次 WSI 分割质量所需的 oracle 局部提示预算。因为每个局部提示点和含目标 patch 的识别均来自 GT，它必须被称为 **oracle click budget**，不能表述为真实用户操作次数。

对每个 WSI—目标类别任务 \(t\)：

- 令本文方法以一次种子正负提示得到的完整 WSI Dice 为 \(D^{ours}_t\)；
- 对 SAM、SAM-Med2D 和 WSI-SAM，预先生成所有含目标 patch 的 GT 引导局部预测；
- 从空 WSI 掩膜开始，按冻结顺序逐一插入一个局部预测；
- 记第 \(k\) 次插入后完整拼接 WSI 的 Dice 为 \(D^{m}_{t,k}\)；
- 首次满足 \(D^{m}_{t,k} \geq D^{ours}_t\) 的最小 \(k\) 定义为 \(K^{m}_{t,reach}\)。

若在该任务全部 \(N_{target,t}\) 个含目标 patch 均已推理和拼接后仍不满足阈值，则记为 **not reached**，而不是把 \(K\) 强行设为成功值。

## 2. GT 模拟提示与单次调用定义

对于每个含目标组织的 patch：

1. 从该 patch 的目标 GT 有效像素中均匀随机抽取 1 个正点；
2. 从非目标有效像素中均匀随机抽取 1 个负点；若不存在非目标有效像素，则该 patch 只使用正点，并单独记录；
3. 对一个 patch 调用一次对应的 SAM 类 `predict` 接口；多候选 mask 的内部选择仍算一次调用；
4. 对不含目标的 patch 不调用模型，拼接为空掩膜。

因此，在通常存在负点的情况下，达到阈值的累计预算为：

\[
C^{m}_{t,reach}=2K^{m}_{t,reach}, \qquad
I^{m}_{t,reach}=K^{m}_{t,reach},
\]

其中 \(C\) 为模拟点击数，\(I\) 为模型调用数。若某些 patch 无可用负点，则按实际冻结 prompt log 统计，不能机械地使用 \(2K\)。

## 3. 顺序敏感性与冻结随机化

逐 patch 结果的累计 Dice 取决于 patch 插入顺序；只使用单一空间顺序会产生偶然偏差。因此，对每个 WSI—类别任务执行 \(R=20\) 个冻结随机排列：

\[
\pi_{t,r}=\operatorname{Permutation}(\mathcal{P}^{target}_t;\;s_{t,r}),\quad r=1,\ldots,20,
\]

其中 \(\mathcal{P}^{target}_t\) 是含目标 patch 集合，\(s_{t,r}\) 由全局随机种子、WSI 标识、目标类别和重复编号确定。三种 SAM 类方法对同一任务使用完全相同的 \(\pi_{t,r}\) 和同一批 GT 随机提示点。

对每个方法报告：

- 每个任务的 \(K_{reach}\)、实际累计点击数和累计调用数；
- 在 20 个排列上的中位数、四分位距和达到率；
- 跨 WSI—类别任务的中位数、均值、95% 分位数；
- 完整运行所有含目标 patch 后仍未达到本文方法阈值的任务比例；
- Dice—调用次数曲线及其 95% 区间。

## 4. 高效计算方式

不需要对每个随机排列重复运行 SAM。每个含目标 patch 只需推理一次并持久化局部二值掩膜/概率图；随后对每个排列在 CPU 上进行增量计数：

1. 初始化 \(TP=FP=FN=0\)，未插入 patch 的预测视为空；
2. 按 \(\pi_{t,r}\) 依次插入一个已缓存 patch 的预测；
3. 只更新该 patch 覆盖像素的 TP、FP、FN 增量；
4. 由累计计数计算 \(D^{m}_{t,k}=2TP/(2TP+FP+FN)\)；
5. 首次超过 \(D^{ours}_t\) 时记录预算，但仍可保存完整曲线用于可视化。

这样，SAM 类模型的实际总调用数仍是每个任务的 \(N_{target,t}\)，而“达到阈值所需调用数”是从缓存预测的前缀曲线中读出的 \(K_{reach}\)。两者必须分别报告，不能混淆。

## 6. 解释边界

- 该协议给局部 SAM 类模型提供了 oracle 的目标 patch 定位，因而是其局部交互性能的有利上界；
- 若某个方法仍需要大量调用或无法达到 \(D^{ours}\)，可说明其局部预测累计到 WSI 级时的效率不足；
- 若某个方法以较少调用达到阈值，只能说明其在 oracle 定位条件下局部掩膜较强，不能据此证明其可从一次真实点击完成全图检索；
- 本文方法的“1 次调用”应定义为完成一个 WSI 任务的端到端 WSI 级推理。若实际实现内部按 patch 批处理，仍应另行报告内部 tile 数和运行时间，避免把工程批处理误称为单次底层网络前向。

## 7. 必要门禁

1. 单任务验证：确认每个含目标 patch 恰生成一次缓存预测，且 `model_calls_full=N_target`；
2. 累计计数验证：随机抽取若干 \(k\)，将增量 Dice 与直接拼接整张 WSI 后重新计算的 Dice 比较，必须数值一致；
3. 顺序验证：相同种子重复得到相同 \(K_{reach}\)，不同冻结排列均被记录；
4. 阈值验证：`D^{ours}_t` 必须来自同一 WSI—类别任务、同一有效像素掩膜，不能使用全数据汇总 Dice 作为单任务阈值；
5. 完成后保存每任务每排列的曲线、达到状态、点数、调用数和随机种子。
